# 设计协作工作台 0.4.4

0.5.0 同时更新负责人端与设计端。修复 NAS 未检查却显示同步成功、断线后不自动恢复、退回修改与改派残留完成时间、通知静音开关方向错误。需求表以隐藏的固定任务编号识别，复制编号会提示核对，改名不再仅靠产品与时间猜测。共享资产查询支持其他设计师记录、历史 NAS 产品目录和别名。后台成功检查只更新同步时间，不重建正在填写的页面。

周月报按统计截止时已保存的任务版本还原，升级前无法还原的任务单列“数据质量”；推定确认时间不混入正式完成点数，不完整计时留空。计时仍是任务运行历时，允许重叠，不能视为人员真实工时。月度 139.2 点仍为排期参考。

0.2.8 将原来按“套”显示和计算的四项标准改为按单张成品计算：主图套图调整 0.3 点/张、SKU 套图调整 0.25 点/张、完整 SKU 精做 0.5 点/张、完整主图精做 0.8 点/张。升级后已有任务会自动重算一次并记录变更。软件界面显示版本号，并统一提高辅助文字、卡片信息、表单说明及状态文字的字号和行高。

0.2.7 修复手工删除正式资产后仍显示“已封存”：负责人端每 5 秒及手动刷新时反查封存文件。某次归档的文件全部不存在时，任务自动恢复为“已完结·待封存”，旧批次保留审计但不再阻止重新上传；只缺少部分文件时会显示缺失数量，待恢复文件或删除该批次其余文件后再处理。

0.2.6 将窗口标题栏与软件顶部合并，移除 Windows 原生文字菜单栏，保留最小化、最大化、关闭按钮，并加入 `Design by Mason Zeng` 署名。负责人端与设计端分别显示自己的窗口身份。启动时会自动重新处理旧版遗留的“请选择资产类别”等失效导入结果。

0.2.5 修正任务事项与资产归档的职责：需求表导入只识别事项与贡献点数，不再要求运营选择资产类别。运营确认完结后，设计端通过“MMDD-设计师-产物类型”文件夹识别主图、SKU、详情页等正式资产类别；同一需求可分别归档多种类型，全部上传后再完成封存。两端必须同时使用 0.2.5。

0.2.4 修复直接编辑 Excel 后状态不同步：负责人端每 5 秒检查五个状态目录，识别原表移动与状态字段修改，更新两端看板。从软件查看需求表改为打开 NAS 原表，保存并关闭 Excel 后自动同步。两端均需更新至 0.2.4，保留已有配置、绑定、任务以及 0.2.3 的整文件夹拖入和工程完整归档功能。

本版包含两个独立 Windows 10/11 x64 安装包：负责人端、设计端。安装后从桌面或开始菜单打开，任务记录真实持久化，使用 HTTPS 内网通信，并由负责人电脑统一读写 NAS。设计端不需要安装 Node.js 或配置服务器。

## 按这个顺序启用

1. 退出托盘中正在运行的旧版负责人端，运行新版“负责人端安装包”，再从桌面打开负责人端并进入“连接与维护”。旧版配置和任务记录会继续使用。
2. 直接连接现有目录：
   - 任务对接库：\\Kyuan_NAS\任务对接库
   - 正式资产库：\\Kyuan_NAS\共享产品主图及详情\00.设计资产库
3. 点击“连接 NAS”，完成读写检查；系统会自动读取五个状态文件夹中的原需求表，也可点击右上角刷新立即检查。新上传需求进入“1.待分配”。命名或内容不符合规则的文件会列出失败原因，由使用者修改后重新导入。
4. 在对应设计师电脑运行“设计端安装包”。负责人在人员卡片点击“连接设备”，复制该人的专属连接码，由该设计师粘贴完成绑定。连接码一小时内有效、只能使用一次。

安装包会建立桌面和开始菜单入口；卸载时默认保留配置和任务记录，便于升级后继续使用。每次测试新版前先从系统托盘完全退出旧版，避免 Windows 继续显示旧进程。

需求文件名严格使用“YYMMDDHH-品牌-任务名-运营-分配情况.xlsx”。任务名最多 10 个字，与 Excel 产品名是两个字段；产品名和 69码从 Excel 的【状态】表读取。未分配写“未分配”，分配后写设计师完整姓名。导入失败列表会直接指出时间、字段段数、任务名字数、人员或 69码的具体问题。
5. 派发任务后，设计端会收到应用内提醒及 Windows 通知；离线期间未查看的分配会在重连后补收。通知是否弹出受 Windows 通知/勿扰设置影响。

## 真实流转

直接修改 Excel 时，请编辑 NAS 原表，保存并关闭 Excel，等待约 5 秒（大表首次同步可能稍长）。也可点击软件右上角刷新，立即核对原表。移动至不同状态文件夹会同步对应阶段；在原位置填写开始日期 H4 / 时间 I4、完成日期 J4 / 时间 K4、确认日期 M4 / 时间 N4，也会分别流转到设计中、待确认、已完结。日期和小时须成对填写。按公司原模板读取，左侧“阶段情况”是合并标题，不作为状态输入。

历史需求已经明确放在“5.已完结”时，文件夹状态可作为完成依据。若 M4 / N4 为空，优先使用已有设计完成时间确定归档日期；两者也为空时使用该 Excel 的文件时间，不要求补填或虚构过去的确认时间。

Excel 占用、多个文件夹内存在同一需求、文件找不到或字段不完整时，任务卡片会注明来源阶段和具体原因。修正后自动重试。有封存文件存在时不能通过改表回退或改派；若某次封存的全部文件已从正式库删除，刷新后自动撤销该次封存并允许重新上传。只删除部分文件会提示具体缺失数量，不会静默撤销。更改产品69码或需求时间会提示负责人核对；未封存任务的事项类型、数量与备注可直接修改，保存关闭后自动重算点数。直接修改 NAS 的操作记录为“NAS 原表同步”，不冒充某个设计师或运营操作。文件移动继续保留原表备份、日志和校验。

从 Excel 新进入设计中的任务，从软件识别到变更时开始精确计时；表中只有整数小时，不能补造之前的精确用时。回退到待设计时停止计时，已有耗时记录保留。

所有任务继续使用现有的五个文件夹：

1.待分配 → 2.待设计 → 3.设计中 → 4.待确认 → 5.已完结

- 负责人分配：自动写入设计师与分配时间，移动原需求表，通知指定人员。
- 设计师开始：开始服务端计时，回填时间并移动需求表。
- 暂停/继续：保存暂停原因，重开软件不丢失累计时间。
- 设计稿仍在聊天软件中交流，点击“已提交，待确认”后停止计时。
- 负责人勾选“运营已在聊天中确认完成”，记录确认并将原需求表移入“5.已完结”。日志会注明是负责人记录，不冒充运营本人操作。
- 设计端随后拖入整个交付文件夹（或点击选择），检查自动归类的数量，勾选自检，再上传封存。归档、校验成功后回填原表 L4 交付地址。封存失败时仍保持“已完结·待封存”，可以重试。

## 数据与权限

- 负责人端默认展示人员卡片；待分配不计入人员负荷，任务列表优先展示待分配。
- 月度基准为 139.2 点；在手点数、本月完成点数独立显示。贡献力只显示“点”，实际设计耗时另行显示。
- 客户端身份在绑定后固定；服务端限制设计师只能操作自己的任务，不能分配任务或确认完结。
- 正式资产按产品69码精确匹配目录；同码目录已存在时沿用其实际品牌目录。多个同码目录、命名错误、同名文件冲突均会阻止封存，不覆盖已有正式文件。
- 已有产品目录的编号按类别名称识别。整文件夹上传自动使用或新建“01.源文件 / 02.导出图片”，分别在其下保留交付文件夹主名与内部相对路径，既有文件不移动、不覆盖。
- 交付文件夹命名：MMDD-设计完整姓名-产物类型，如“0903-吕慧芸-主图”。日期取运营最终确认日，上传区会显示此事项的准确名称。校验整包名称、有效文件名及至少一份最终产物与源文件，设计师核对数量后封存；内部文件名保持原样，无需将每个 PSD 改为文件夹同名。
- 图片产物只识别 PNG、JPG（兼容 JPEG，大小写不限）；其他格式归源文件。创意视频事项继续以 MP4 为最终产物，工程事项全部归源文件。普通子文件夹内图片也能识别，保留相对路径。
- 支持主图、SKU、详情页、六面图、创意图、创意视频和工程文件。单个文件上限 8 GB，每次封存总量 20 GB、最多 500 个文件。
- 含 C4D、Blender、3ds Max、Maya、AE、Premiere、Unreal、Unity 工程文件的一级子文件夹整体归源文件；其中的图片属于工程依赖，保留在原位置，不计入最终产物。若工程主文件直接在交付根目录，则所有子目录跟随源文件。名为“源文件 / 工程 / source / sources”（可带数字编号）的子目录也整体保留。零字节附件和空目录可保留；链接目录、快捷链接及超深目录会阻止上传，避免工程依赖丢失。系统索引文件 Thumbs.db、desktop.ini、.DS_Store 不上传，无需压缩成 ZIP。
- 每份需求表对应一个产品69码，支持多个事项。需求事项只负责贡献点数；资产类别在设计端最终上传时按交付文件夹名称识别。未知事项类型或缺69码的文件不能进入正式流转。
- 原有需求导入前的准确耗时无法由表内整数小时还原：原“设计中”任务会暂停，设计师点击继续后开始准确累计；历史计时不补造。计时按真实经过时间累计，非工作时间需主动暂停。

## 负责人电脑保持运行

关闭窗口会收起到系统托盘，服务仍在线。负责人退出软件、关机、休眠或网络中断时，设计端保留最近信息并自动等待重连，操作暂时停止。

可在“连接与维护”开启开机启动。负责人电脑建议使用固定内网地址或 DHCP 地址保留。两台电脑需要能互相访问 TCP 47831。

如公司 Windows 防火墙阻止连接，请让 IT 仅允许负责人程序在公司专用/域网络、内网子网访问 TCP 47831。安装包不会自动修改防火墙或开放公网端口。

## 备份与恢复

数据库及加密设备配置保存在对应 Windows 用户的应用数据目录，卸载默认保留。负责人可以点击“备份任务记录”，将一致性数据库备份保存到 NAS 的 _workbench-system/database-backups。

_workbench-system 是运行记录与备份目录，_workbench-staging 是未完成上传的暂存目录；任务本身仍只在五个状态文件夹中流转。文件变更前会保留原表备份和同步日志；不删除这些记录。任务表被 Excel 占用或外部修改时，软件会阻止覆盖并提示处理。

同一任务库只允许一个负责人服务写入。电脑异常退出后，服务租约最多两分钟过期；重新启动时自动尝试恢复同步日志。设备更换、数据恢复与跨版本升级应保留完整应用数据目录，并重新检查绑定。

## 本版实机检验建议

先确认负责人“NAS 已连接”，再在另一台电脑绑定设计端。走一遍分配、查看、开始、暂停、待确认、确认完结、封存，检查原 Excel 所处文件夹、时间字段和交付地址。命名不规范应上传失败，同名资产应拒绝覆盖。断开设计端网络后重新连接，未读提醒与任务应恢复。

软件未使用企业代码签名证书签名；请按公司软件安装规范处理。此版本已完成开发机上的双客户端协议和 NAS 读写联调，第二台实体电脑的防火墙、Windows 通知显示和公司网络策略仍需现场验收。

## 固定任务编号与历史版本

内部编号存入 Excel 隐藏定义名称，不增加填写项、不修改可见模板。复制已有任务表不能直接当新需求导入，请使用空白模板。旧版文件尚未补编号前，如果文件名和内容同时变化、又无法通过内容校验确认原任务，会明确要求恢复原文件名后同步，避免串单。

任务版本从升级后开始记录，已有数据库在打开时保存基线；无法恢复升级前任意日期的真实历史，报表不会拿今天的数据冒充过去。版本、任务和事件在同一 SQLite 事务中保存。周报固定周一至周日，周 32 点与月 139.2 点均为容量参考。质量/时效责任判定、专注计时规则、同名归档批次的目录变更尚未在此版本实施。

## 0.6.21 负责人回退

任务卡片新增“回退”：已封存→待封存→待确认→设计中→待设计→待分配。每次回退一步并确认清理范围，同步移动原表、清理失效时间及评分，保留原表备份与操作历史。离开已完结环节后，旧交付改为历史，旧上传不会自动恢复；重新交付保存在源文件/图片目录各自的返工批次子目录。不会删除原交付文件。原表重复、Excel 占用或文件正在发布时会提示处理原因，不强行覆盖。运营端无需更新，刷新后读取回退后的原表。
