# 设计协作工作台

基于公司 NAS 的设计需求、任务流转和产物归档系统。此仓库统一保存三个客户端，与 Relay 图片工作台分开维护。

| 客户端 | 当前安装包 | 源码目录 |
| --- | --- | --- |
| 负责人端 | 0.6.21 | desktop/、ui/、core/ |
| 设计端 | 0.6.21 | desktop/、ui/、core/ |
| 运营端 | 0.2.11 | operator/、core/ |

安装包在 Releases 下载。负责人主机应先更新，再更新其余客户端。运营端安装包沿用已有 0.2.11，未重新构建；源码为本次整理时的工作区快照，共享 core 后续构建时以仓库内容为准。

## 0.6.21

负责人卡片新增逐级回退：已封存 → 待封存 → 待确认 → 设计中 → 待设计 → 待分配。清理失效时间、评分和当前交付关联，保留原表备份、历史记录和原产物。返工产物另存批次目录，旧上传不会自动成为新交付。运营端无需升级，刷新后读取回退原表。

以下目录缓存与布局调整从 0.6.20 延续：

- 保留 0.6.19 原需求表保存后同步、展示实际流转错误的修复。
- 弹窗避开窗口右上角按钮，面板内容独立滚动。
- 产品目录索引持久缓存；NAS 目录手动变更后点击“更新目录”。
- 普通及后台刷新跳过已完结原表和归档文件；负责人可点击“刷新已完结”单独核对。

## 开发和打包

使用 Node.js 24 或更新版本，Windows 下构建安装包：

```powershell
npm ci
npm start
node scripts/build.cjs manager nsis
node scripts/build.cjs designer nsis
node scripts/build-operator.cjs
```

构建结果保存在 release/。两端各自使用独立的应用标识和用户数据目录。

## 验证与数据

0.6.21 负责人端和设计端已完成相关测试、启动检查及弹窗布局检查。运营端存在尚未修复的既有测试失败，本次仅归集其源码和已有安装包，不声明全仓测试全部通过。

此仓库不包含运行数据库、登录凭据、连接码、NAS 上的真实需求表或交付资产。GitHub 源码备份不能代替业务数据备份。首次部署仍需配置公司 NAS、内网连接与客户端身份。
