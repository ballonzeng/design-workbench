# 设计协作工作台

基于公司 NAS 的设计需求、任务流转和产物归档系统。此仓库统一保存三个客户端，与 Relay 图片工作台分开维护。

| 客户端 | 当前安装包 | 源码目录 |
| --- | --- | --- |
| 负责人端 | 0.6.34 | desktop/、ui/、core/ |
| 设计端 | 0.6.34 | desktop/、ui/、core/ |
| 运营端 | 0.2.16 | operator/、core/ |

安装包在 Releases 下载。负责人主机应先更新，再更新其余客户端。

## 0.6.34 / 运营端 0.2.16

未归档任务的原需求表仅更正69码时，工作台根据固定任务编号核对同一份原表后，自动同步任务和各事项的69码，清除旧异常提示，保留任务编号、点数、分配、查看和计时记录。已完结但未封存的任务保留确认时间、所属月份及评分，旧上传批次自动失效；重新选择产物即可使用更正后的69码归档。点击流转时只因本次69码同步发生的版本变化可继续执行，其余任务变更仍需刷新核对。

运营端在本人需求详情新增“更正69码”，待分配、待设计、设计中及待确认均可单独修改；更正前检查唯一原表、Excel占用及并发保存，并在NAS系统恢复目录保留原表及修改记录。更正不解除原表保护，也不开放待设计/设计中整表编辑。已有归档产物或正在发布的任务不会自动切换产品关联，仍通过负责人核对及原有回退机制处理。

修复运营更正与负责人流转同时发生时，旧流转快照可能把69码改回旧值的问题：移动原表后再次核对实际备份，发现新保存则保留最新版本并撤销本次流转。已完结未封存的原表若同时更新评分，将一并同步最新评分。

先更新负责人主机至0.6.34，再更新运营端0.2.16。此前已在Excel更正69码而卡住的未归档任务，更新主机并同步需求后即可继续；无需删除或重建任务。

## 0.6.33 / 运营端 0.2.15

支持2.3版需求模板新增的「产品视频」「包装设计」事项及「视频」「包装」工作表。在【状态】页的数量列填写计量数：产品视频每个分镜2.5点（8分镜20点），包装设计每套方案4点（2套8点）。包装页的方案数量引用状态页；视频页预置镜号和示例不作为独立计分来源。旧版三种创意视频仍按原单价和条数计算，历史点数不变。

任务卡片、运营评分和报表使用相同的计分标准。新增包装设计归档分类，支持「包装」「包装设计」文件夹；产品视频文件夹可使用「产品视频」别名。分镜数不要求等于视频文件数，方案套数不要求等于导出图片数；包装图片可保留原名并纠正重名。负责人端、设计端和运营端都需更新以完整支持新事项。

## 0.6.32 / 运营端 0.2.14

修复 Excel/WPS 或确认操作中断后，遗留 `~$` 占用记录导致任务一直无法同步的问题。Windows 会在原表及占用记录静置两分钟后，核对两者的实际读写占用；只有同时取得排他读写句柄，才将遗留记录移到 NAS 系统恢复目录并自动继续同步。原表不写入任何内容。仍被编辑、权限不足、网络错误及检测失败时继续保留记录并停止操作。自动同步、任务流转、改名导入、点数校准和运营确认使用同一规则。

## 0.6.31

运营替换未开始的需求表时，如果原表放在待分配目录但已填写有效设计师和分配时间，自动移到待设计并同步最新事项、数量和点数。保留原任务编号及同一设计师的分配、接收和查看记录。新导入及改名后的原表也使用同一规则；已有计时、交付、封存历史或正在上传的任务继续要求核对，不自动回退。运营端沿用 0.2.13。

## 0.6.30

## 0.6.29 / 运营端 0.2.13

## 开发和打包

使用 Node.js 24 或更新版本，Windows 下构建安装包：

```powershell
npm ci
npm start
node scripts/build.cjs manager nsis
node scripts/build.cjs designer nsis
node scripts/build-operator.cjs
```

构建结果保存在 release/。两端各自使用独立的应用标识和用户数据目录。

## 0.6.22 回退提速

回退到待封存只撤销当前任务封存标记，保留文件，不执行全量 NAS 扫描。其他环节回退只核对当前需求表，保留版本、占用与重复原表校验。98 项相关测试、两端启动与安装包源码核验通过。另一对话未发布的封存一致性修改未包含在本版本中。


## 0.6.23 更正69码后回退

负责人可在回退弹窗勾选采用原表中更正后的69码，将更正与回退一起保存。仅允许同一固定任务编号、仅69码变化的原表；权限、版本、重复原表、Excel占用和文件哈希检查保留。旧交付、原码及文件保留为历史，不移入新码目录。101 项相关回归测试通过。
